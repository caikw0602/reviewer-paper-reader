# 分层交付、独立核查与学习检验

用于标准精读交付，也在独立核查、互动或续读请求时读取对应分支。优先让读者拿到清楚可用的解释；检查记录服务判断，不以报告长度证明完成。

## 1. 输入到输出的使用约定

| 输入情况 | 可交付内容与边界 |
|---|---|
| PDF／可访问全文 | 主阅读页、机制、贡献、证据与研究诊断；按实际范围说明附录和图表覆盖 |
| Zotero题名／条目 | 先确定唯一条目与附件，核对版本；重名按作者／标识辨认，缺全文时说明受影响判断 |
| DOI／arXiv／网页 | 获取原始公开版本并记录，相关全文不可访问时限定分析 |
| 摘要／节选 | 基于提供部分建立问题与初步思想；依赖全文的协议、实验和创新保留待核验 |
| 用户限定速读或单点 | 直接满足当前问题，标重要未覆盖项，不强制全部研究与审计产物 |

个人方向、基础与预算从上下文利用；未说明时默认中文、先直觉后必要细节，标准精读带一个优先研究问题。新问题需要当前资料，旧笔记不替代重新查新。

## 2. 默认分层产物

**对话主阅读页**通常以约600–1000中文字为起点，按复杂度及用户预算调整：

1. 任务／约束、基线与具体瓶颈。
2. 最小思想与一个清楚的新旧对照；用最短必要例子帮助推演。
3. 这篇论文增加了什么认识：主要关系、成立条件、证据性质与关键例外；没有确立规律时直说。再给关键效果与贡献判断，避免把解释和已证结论混写。
4. 最值得先回答的研究问题及下一动作，或暂不提出方向的依据。
5. 详细记录链接与关键来源；纯对话模式保留可追溯出处。

**详细Markdown**沿主张组织以下材料，避免重复六份章节摘要：

- 来源身份、本轮范围、实际阅读顺序及重点位置。
- 核心思想、必要图／公式、一次运行、条件和反事实。
- 一至两项主要认识：新发现／借用／解释假设的身份、适用范围、证据和例外；适配论文类型，不把所有结果升格为规律。
- 近邻比较，技术差异／新颖性／价值的分别判断。
- 主张—证据—替代解释—支持范围，必要数值和成本口径。
- 作者局限与展望、本次推断分别标记；一个研究候选的诊断与决策。
- 来源定位、未读／未取得／未报告／反证、下一阅读位置。

每项判断保留一处主记录，其余引用。先准确解释作者论证，再展示核查及修正版；语气公平，来源解释了某疑点就删除不成立的批评。

**核查记录**按实际工作量另存或并入详细Markdown：检查对象、原始证据、结果、必要修正、仍未知，以及静态／汇总复算／原始重算／运行复现的范围。只在实际生成有价值时输出CSV、脚本、图像等附属文件。

### 保存约定

服从用户路径和既有项目约定；无约定时使用当前任务工作区的 `output/paper-reading/<论文短名>/`，标准文件可为 `阅读记录_v01.md`、`来源核查_v01.md`。续读递增或按明确要求更新，保留原始PDF及重要历史稿。文件交付使用实际绝对路径链接。没有可写本地目录时以对话完成并说明保存未执行。

## 3. 独立核查：有条件执行的两阶段过程

用户明确要求独立核查／独立复核，且有可用、授权的独立子代理时，派一个独立上下文先读取最少必要原始材料；不给主稿、预设结论、疑似错误或修法。不能取得独立上下文时，完成可做的来源复核并标明“未执行独立核查”，同上下文重读不称盲核。独立核查不替代原始实验复现。

**阶段A，来源先行：**核查者先记录核心机制、关键规则／数字、容易误读的协议及未知。来源底稿形成后再冻结主阅读稿，记录哈希或等效版本身份。

**阶段B，稿件对照：**核查者读取冻结稿，对照来源，优先找会改变机制、创新或研究设计的必要修正，再看措辞与一致性。研究实验要检查是否真能区分中心解释、权限与预算是否可比、真值和否定结果是否定义。允许结论为未发现重大错误或材料不足。

先交付简短可操作结论，详细来源另存；把成立的修正落实到核查后稿，保留冻结稿、原始意见与修订对应。报告实际核查对象和未完成项，不以多个模型一致代替事实来源。定向补问可以在来源底稿后进行，标明其发生阶段，不能倒写成完全不知结论的盲查。

核查记录建议分为：严重错误、必要修正、可选增强、确认通过、仍未知。不强制每栏有问题，不为了严厉保留已被证据排除的批评。

## 4. 真实理解检验

非互动阅读不要求用户先答题。可以给少量论文相关自检点，未答时记待检验，参考答案按需要单独放置。

用户要求互动时，一次聚焦一个障碍，等待真实回答，再定位是术语、信息流、数学、设计理由还是证据判断的问题；最小补讲后用新情境复测。优先检验：

- 不借模块名复述瓶颈与关键改变。
- 让一个新样本走通，并说明当时可用的信息。
- 改变成立条件后预测行为，区分结果提升与机制归因。
- 分清论文发现的关系、用于利用它的方法和具体实现；说出一个例外或尚未验证的条件。
- 提出一个简单替代方案及可区分实验。

仅根据实际作答记录掌握与误区；完整报告、助手自测答案和来源核查都不证明用户已经学会。

## 5. 续读与使用反馈

续读先查已读范围、修正过的判断、未解问题与真实学习记录，再处理新问题；新消息通常在原目标上转向，不自动重写全篇。

用户反馈某处难懂或不实用时，记录具体触发条件、原输出问题、期望行为与最小改进建议。修改skill版本需来自用户请求；保持来源记录与技能说明分离，使用中形成的论文事实不自动写入通用skill。没有对照、留出与读者表现数据时，只报告实际观察，不宣称节时或学习效果提升。
